# Media Upload Troubleshooting

StreamCore **v0.3.1-alpha** fixes the media upload experience on mobile browsers.

## Upload pipeline

```text
Browser file → HTTPS XHR (percentage/cancel)
            → Caddy → FastAPI POST /api/media/raw
            → /opt/streamcore/media (direct streaming)
            → ffprobe H.264 validation → SQLite media index
```

The legacy multipart `POST /api/media` is still supported, but the browser
now uses the raw streaming endpoint to avoid temporarily storing another full
copy in `/tmp`. Files are only listed after codec validation succeeds.

### Understanding progress

- **0–99%**: browser is sending bytes over HTTPS. Speed depends on the device's upload connection.
- **100%**: the browser has finished sending the body, but the server may still be validating H.264 video with ffprobe (up to 30 seconds, excluding database/disk work).
- **HTTP 413**: file exceeds `MAX_UPLOAD_MB` (default 1024 MB).
- **HTTP 422**: unsupported extension, empty file or no H.264 video stream.
- **HTTP 507**: server disk is full.
- **Network error**: browser connection dropped or reverse proxy interrupted.
- **Cancel**: stops the request; the server removes any incomplete file it created.
- **Stalled indefinitely**: check server disk space, Docker logs and reverse proxy. Sending large files over mobile can take many minutes.

The file upload runs **from your browser to VPS**, but video broadcasting itself
remains independent of your phone and PC once the upload has completed.

### Debug on your VPS

```bash
cd /opt/streamcore
docker compose ps
docker compose logs --tail=80 dashboard caddy
df -h / /opt/streamcore/media
df -i /opt/streamcore/media
```

Do **not** share your `.env` contents, admin password, session secret, or RTMP Stream Keys in logs or screenshots.

### Update an existing installation

Complete/cancel any pending upload first, then via SSH:

```bash
cd /opt/streamcore
git pull --ff-only
docker compose up -d --build
docker compose ps
```

The `.env`, SQLite state, and media directory are preserved across this update.
Video streaming restarts briefly when the dashboard is rebuilt.

### Floating color-bar video on mobile

The SMPTE-style color bars are generated by the test stream. Prior versions
could leave the HLS preview playing after navigating to **Media Library**.
The updated UI stops HLS on other pages and explicitly disables Picture-in-Picture.
On Android, you may still need to close a Picture-in-Picture window previously
created by the browser before refreshing.

## Validation status

The JavaScript was parsed successfully and DOM references were checked. API tests
for the raw upload route and cleanup were added to the test suite. This fix
must still be validated end-to-end on a live VPS and a mobile browser.
